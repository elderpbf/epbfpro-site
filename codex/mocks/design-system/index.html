Codex · Design System

Mock para aprovação · cada componente, estado, claro + escuro · nada aplicado ainda

1 · Paleta (camada de cor, nomeada por cor)

Conjunto reutilizável de matizes, nomeado pelo que é, nunca pelo que colore hoje. Theme-stable: a matiz nunca vira texto nem preenchimento sólido, só aparece via o padrão accent-card (tinta + ponto da cor).

--acc-teal

2 · Atribuição (semântico → paleta)

Que aba/categoria usa qual matiz. Único lugar onde esse mapa existe, recolorir uma aba é uma linha. Os componentes referenciam o nome semântico.

Aula → indigo
Conteúdo → teal
Turmas → amber
Questões → pink
Certificados → violet
Drive → blue
Externo → orange
Tarefas → red

3 · Papéis semânticos (claro + escuro deliberados)

Cada papel tem um preenchimento sólido + texto-sobre-preenchimento (ações/zonas) e uma tinta + texto-da-tinta (pills/badges). No escuro os preenchimentos aprofundam e os textos-da-tinta clareiam, nunca um sólido aceso.

tint primary

tint success

tint danger
success/danger fill cells reuse the danger-solid look only to show the fill swatch; real roles wire their own tokens.

4 · Botões

A regra: contexto + ênfase, de propósito. Botões gerais/de barra são neutro preenchido; ações pequenas de linha são vazadas (Editar/Duplicar); destrutivas inline (Excluir/Revogar) são danger vazado (preenche vermelho só no hover). Vermelho sólido só no passo final de confirmação, no modal.
Os tiers
passe o mouse pra ver hover/focus · cada tier tem :hover, :focus-visible, :disabled · tamanhos --sm / --lg

Prompt para diagnóstico tributário

6 · Accent-card (o único jeito de uma matiz de categoria renderizar)

Tinta fraca da matiz (aprofunda no escuro) + borda da matiz + texto neutro + ponto/ícone da matiz. É o que as seções de Aula, as zonas e os cabeçalhos coloridos usam.
